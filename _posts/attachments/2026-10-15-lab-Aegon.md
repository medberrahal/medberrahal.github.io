# Investigation secdojo.net : d'un fichier HTA piégé à la compromission du domaine

> **Source :** OpenSearch, index `winlogbeat-*` (21 au 28 mars 2024)
> **Heures :** UTC
> **Résultat :** ✅ chaîne d'attaque complète reconstituée, du phishing initial jusqu'à l'exfiltration de `ntds.dit`


## 1. Synthèse

L'utilisateur **Vhagar** télécharge `invoice.hta` sur le poste **helpdesk** (Sysmon 15). L'attaquant y installe un beacon **Cobalt Strike**. Il lance `mimikatz`, puis pivote vers **SRV01** avec le compte `joe` en **Pass-the-Hash**.

Sur SRV01, il abuse d'**ADCS** avec **Certify** pour usurper `adm_infra`, vole et injecte un TGT avec **Rubeus** (**Pass-the-Ticket**), puis atteint le contrôleur de domaine. Sur le DC, il copie `ntds.dit`, tente de créer le compte `Aegon` et consulte une GPO personnalisée.

### Q5 — Journal et identifiant d'événement

```json
GET winlogbeat-*/_search
{ "size": 50, "sort": [{ "@timestamp": { "order": "asc" } }],
  "_source": ["@timestamp","host.name","event.code","winlog.event_id","log","message"],
  "query": { "bool": { "should": [
    { "query_string": { "query": "invoice.hta" } },
    { "term": { "event.code": "15" } } ],
  "minimum_should_match": 1 } } }
```

**Sortie pertinente :** `event.code = 15` avec le message `invoice.hta`. Journal Windows : `Microsoft-Windows-Sysmon/Operational`. L'événement Sysmon 15 est **FileCreateStreamHash** : il enregistre la création d'un flux de fichier (ici le `Zone.Identifier` d'un fichier téléchargé) avec son hash.

**Réponse :** log file : Sysmon, eventID : 15

### Q6 — C2 associé au malware

```json
GET winlogbeat-*/_search
{ "size": 100, "sort": [{ "@timestamp": { "order": "asc" } }],
  "_source": ["@timestamp","host.name","event.code","winlog.event_data","process.name","process.command_line","process.executable","message"],
  "query": { "query_string": { "query": "5ac8f30 OR ADMIN$ OR beacon OR Cobalt OR invoice.hta" } } }
```

**Sortie pertinente :** `\\srv01\ADMIN$\5ac8f30.exe`, puis `5ac8f30.exe`, `services.exe` et `rundll32.exe` sur SRV01. Cette chaîne (binaire écrit dans `ADMIN$`, service installé, `rundll32` en processus enfant) correspond au **jump psexec de Cobalt Strike**. Les connexions régulières de `powershell.exe` (helpdesk) vers `192.168.142.128:80`, toutes les minutes, sont compatibles avec un beacon HTTP.

**Réponse :** CobaltStrike

> ⚠️ **Remarque :** `5ac8f30.exe` est un nom de payload, pas la réponse. Cette identification est une déduction à partir du comportement observé ; aucun log ne contient le nom « Cobalt Strike » en clair.

## 6. Recommandations

- Corriger le template `vulnct` (retirer « le demandeur fournit le SAN ») et auditer ADCS.
- Réduire NTLM, activer Credential Guard et protéger LSASS.
- Réinitialiser `krbtgt` deux fois et tous les mots de passe, car `ntds.dit` a été copié.
- Restreindre `ADMIN$` et la création de services à distance. Surveiller les événements 4697 et 7045.
- Auditer la GPO `{87EA95E6-...}` et ses scripts de démarrage.
- Activer et centraliser les événements 4720, 4741 et 5136, absents de cet index.

## Leçons retenues

- Une détection peut reposer sur une **chaîne comportementale** plutôt qu'une signature explicite : aucun log ne contenait le nom « Cobalt Strike » en clair, mais la combinaison (écriture dans `ADMIN$`, service installé, `rundll32` en processus enfant) suffisait à identifier la technique du jump psexec.
- Une réponse obtenue par une première requête (`192.168.142.132` pour Q11) peut être incorrecte si elle correspond en réalité à une autre machine du même scénario — toujours croiser avec plusieurs event codes avant de conclure.
- Documenter explicitement les **réserves méthodologiques** (comme pour Q7 et Q18) est une bonne pratique DFIR : cela distingue ce qui est prouvé de ce qui est déduit, et donne une piste claire pour affiner l'investigation si une réponse est contestée.
- Le même LUID Kerberos (`0x1db074`, `0x20a882`) réutilisé dans plusieurs commandes Rubeus `ptt` est un indicateur fiable pour relier des actions d'un attaquant entre elles, même à travers plusieurs étapes de la chaîne.

## Références

- Event ID Sysmon **15** — FileCreateStreamHash
- Event ID Windows Security **4624/4625/4648/4768/4769** — authentification et tickets Kerberos
- Event ID Windows Security **5145/4697/7045** — accès réseau et création de service
- Event ID Windows **4100** — erreur d'exécution PowerShell (journal PowerShell)
- Outils offensifs : **Certify** (abus ADCS), **Rubeus** (Pass-the-Ticket), **mimikatz** (dump d'identifiants)
